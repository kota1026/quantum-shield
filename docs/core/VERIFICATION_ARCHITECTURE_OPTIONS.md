# Unlock 検証アーキテクチャの選択肢 — 競合比較と Pros/Cons

> 2026-08-26 作成。`STARK_AIR_GAP_ANALYSIS.md` §21〜§32 の実測と
> `docs/research/COMPETITOR_ANALYSIS_2026.md`、および Strategy_weekly vault の
> 外部調査（EIP-8051 / 8202 / 8292、leanSpec）を材料にしている。

## 0. なぜこの整理が必要になったか

`SEQUENCES.md` v3.0 の元設計は **経済的セキュリティモデル**だった ——
監視ボットが Dilithium 検証で不一致を検知し、Challenger が bond を積んで異議、
不正なら Prover を Quadratic Slashing（報酬配分 Challenger 60% / Insurance 20% / Burn 20%）。
L1 は「異議が出なければ通す」。

`ONCHAIN_TRUST_MECHANISM_REQUIREMENTS.md` の **FR-THRESH-1** はこれを
「STARK proof 検証を経由した強制」に置き換える要件として後から追加された。
その動機は「オンチェーンでのフル検証は高すぎる」という前提にあったと読める。

**この前提は 2026-08 の実測で崩れた。** 当時 673.8M gas を要していたのは
`SPHINCSVerifier.sol` の実装が FIPS 205 非適合で壊れていたためであり（§21）、
正しく実装すると **SLH-DSA 2.42M / ML-DSA 2.67M**（いずれもブロックの 8%、§27・§31）。

よって 3 方式を横並びで評価し直す。

---

## 1. 三方式

| | 検証の主体 | 信頼前提 | 実装状態 |
|---|---|---|---|
| **A. 経済的モデル**（元設計） | 監視ボット + Challenger（L3 エコシステム） | **あり** — 誠実な監視者が最低 1 人存在すること | 実装済み（Sequence #4） |
| **B. L1 直接検証** | L1 コントラクト | **なし** | **実装・実測完了**（§25〜§29） |
| **C. STARK proof 経由**（FR-THRESH-1） | L1 が proof を検証 | なし（ただし wrap 次第） | 未完（集約が残、最終段が原則違反 §23） |

---

## 2. Pros / Cons

### A. 経済的モデル（Optimistic + Slashing）

| Pros | Cons |
|---|---|
| **ガスが最も安い**。L1 は異議の有無を見るだけ | **CP-5「全てオンチェーンで検証可能」に反する**。Phase 2 はこの乖離を埋めるために始まった |
| 実装済みで動いている | **誠実な監視者の存在を仮定**する。監視が止まれば不正が通る |
| Challenger への報酬設計があり、監視のインセンティブが内在 | **タイムロック 7 日**が必須。資金効率が落ちる |
| 署名方式に依存しない（PQ でも古典でも同じ枠組み） | 量子攻撃者は「監視されていない瞬間」を突けばよく、**PQ 署名の意味が薄れる** |

**競合との関係**: QRL / QANplatform はいずれもこのモデルではなく、
**チェーン自体を PQ にする**方向。A は「PQ 署名を使うが強制は経済的」という
中間形で、**耐量子を掲げる製品としては説明が難しい**。

### B. L1 直接検証

| Pros | Cons |
|---|---|
| **信頼前提ゼロ**。CP-5 を実際に満たす唯一の構成 | **ガスが高い**。2-of-N で 4.85M（SLH-DSA）/ 5.35M（ML-DSA）= ブロックの 16〜18% |
| **実装・実測完了**。参照実装に層ごとに固定済み（§25〜§26） | メインネットで **1 回 $145〜$291**（10〜20 gwei 想定）。低頻度・高価値の操作なら許容範囲だが安くはない |
| **厳密な FIPS 205 / 204 適合**。CP-1 と衝突しない（§24） | **閾値の上限**が 11 署名（§31）。それ以上は集約が要る |
| **EIP-8051 が入れば ML-DSA 側は 4,500 gas**（1/594、§32.2） | EIP-8051 は Draft。時期は制御外。SLH-DSA 側の precompile 提案は無い |
| 外部への実行時依存がゼロ | 新規に書いた暗号実装であり**未監査** |

**競合との関係**: QANplatform は Dilithium + ECDSA のデュアル署名だが
**ECDSA を残している**（古典仮定が残る）。B は**古典仮定を一切持たない**点で上を行く。
QRL は XMSS→SPHINCS+ 移行中で 7 年無事故だが、**スマートコントラクトは EVM 互換を
これから追加**する段階。B は既存 EVM 上で成立する。

### C. STARK proof 経由（FR-THRESH-1 の原案）

| Pros | Cons |
|---|---|
| **N に対してフラット**。閾値が二桁になっても L1 コストが増えない | **未完**。`recursion-verify-m05` は 4 proof / 0.7 MB で非集約（§20） |
| EIP-8292 が定義した**アグリゲータ役割に最も近い資産**（19,252 行） | **最終段が原則違反**。集約 → Groth16 wrap の計画は BN254 の古典仮定を検証層に持ち込む（§23） |
| proof サイズは小さくできる | **代替の wrap も未検証**。WHIR ベースなら軸は満たすが EVM 検証コスト未測定（§32.5） |
| | **Poseidon2 が CP-1 と衝突**（§32.1）。FIPS 準拠層との切り分けが未決 |
| | 現行 2-of-N では**そもそも不要**。B で足りる（§31） |

**競合との関係**: この役割は **EF 自身が leanVM（WHIR + SuperSpartan + Logup）で
実装しようとしている**。EIP-8292 は「PQ 署名は BLS と違い加算で結合できないため
アグリゲータ役割が要る」と定義しており、**パーミッションレスな役割**。
Strategy_weekly のレーン D は **Q3（既得権益が動けない理由）不成立**と判定している
—— EF は構造的に動けないどころか最速で動いており、Gap が無い。

## 3. 判断への示唆

### 3.1 A と B は排他ではない

B があれば A の Challenge は**不要になる**（暗号的に確定するので異議の余地が無い）。
あるいは A を残し、**異議が出たときの裁定手段として B を使う**構成もありうる
（通常時は安く、争いが起きたときだけ 4.85M を払う）。後者は
**ガスと信頼前提のトレードオフを運用で調整できる**。

### 3.2 C は「N が二桁」でなければ要らない

§31 の実測が示す通り、直接検証は 11 署名までブロックに収まる。
現行の 2-of-N では C の利点が発現しない。
C を追う理由があるとすれば **EIP-8292 のアグリゲータ役割を狙う場合**だが、
それは資産保護プロトコルとは別の事業判断であり、レーン D は Q3 不成立と判定している。

### 3.3 競合比較から見た B の位置

`COMPETITOR_ANALYSIS_2026.md` は「NIST 準拠は差別化要因ではなく**最低要件**に
なりつつある」と書いている。その通りだとすると:

- 「Dilithium + SPHINCS+ を使っている」は差別化にならない
- **「検証層まで古典仮定を一切持たない」は差別化になりうる**。QAN は ECDSA を残し、
  Groth16 wrap を使う設計は検証層に楕円曲線を戻す。B はそこを持たない
- ただしこれは**説明可能性**の差であり、実測で裏付けが要る。§27・§31 がそれにあたる

### 3.4 未解決

- **FR-THRESH-1 を維持するか改訂するか**は要件レベルの判断であり、本ドキュメントの範囲外
- B を採る場合、**A（Challenge/Slashing）を残すか撤去するか**の設計判断が残る
- B の**独立監査**は未実施。参照実装との一致は必要条件であって十分条件ではない
