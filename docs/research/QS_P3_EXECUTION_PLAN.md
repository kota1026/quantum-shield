## 0. 実行テーゼ

P3 の勝ち筋は「署名」ではなく **カストディ強制・閾値-PQC・規制準拠**。よって本計画は次の順で価値を積む：
1. **信頼の土台**（クリプト正しさの継続証明）＝ WS4。これが崩れると他が全部無効。
2. **差別化の中核**（閾値-PQC カストディ＋オンチェーン強制）＝ WS2・WS3。
3. **将来対応**（アジリティ＋87 ティア）＝ WS5。
4. **物語と監視**（再ポジショニング＋トリガー）＝ WS1・WS6。

## 2. ワークストリーム詳細

### WS1｜再ポジショニング & GTM（柱A）
- **成果物**:
  - 1ページャ「Chain-agnostic PQ Custody & Policy Layer」。前面に **閾値-PQC ギャップ**と **HNDL 露出**（休眠資産の恒久公開鍵）。
  - **ICP 定義**: 機関カストディ／トレジャリー／ファンド／長期ロック（veQS 4年＝T3 候補）。
  - メッセージ転換: 「Ethereum で PQ 署名」ではなく「**どのチェーンの PQ 移行が勝っても生き残るカストディ強制層**」。
- **やらない**: 自己申告 TPS 等のマーケ、目前 Q-day 煽り（`QS_STRATEGY_2026` §5）。

### WS2｜閾値-PQC カストディ設計（柱A・製品中核）
- **背景**: 既存カストディ（Fireblocks $8B）が **MPC/閾値-PQC を未解決と自認**（E5）。ML-DSA/SLH-DSA にドロップイン閾値版が無い。ここが 1-3年の先行窓。
- **QS の素地**: 既に **2-of-5 Prover 閾値**（`L1Vault.sol`: `REQUIRED_SIGNATURES=2`, `TOTAL_PROVERS=5`）＋デュアル署名（ML-DSA + SLH-DSA）。
- **成果物**:
  - 閾値-PQC カストディ設計ノート: 定足数・ロール・鍵分散モデルを機関カストディのポリシー（承認フロー・緊急経路・タイムロック）へマッピング。
  - **対 Fireblocks ギャップ分析**: 「なぜ MPC 勢が今出せないか／なぜ QS のネイティブ PQ 閾値が答えになるか」。
  - デュアル署名の閾値化（M-of-N を lattice と hash の各系で独立に取るか、合成するか）の方式比較。

### WS3｜正直なハイブリッド強制 ①（柱B / D1=a）
- **目的**: `PQ_RESISTANCE…` §3 の**荷重部材①**を埋め、「オンチェーンで強制可能な PQ カストディ」を事実化。
- **サブタスク**:
  1. **SPHINCS- 紛争パス加速器 PoC**: 目標 ~127K gas。正典は FIPS 205 SPHINCS+（L3 オフチェーン検証）を維持、L1 は**紛争時のみ**検証（CP-1 自壊を避けるため中核署名は据え置き・§5 Non-Goal 2）。
  2. **FIPS205 ↔ SPHINCS- メッセージ等価マッピング**（正典と加速器の暗号学的接続）。
  3. **Fraud-proof 提出フロー**＋ **permissionless Watcher/Challenger の経済設計**（`SEQUENCES` #4 の報酬を運営専属でなく開放）。
  4. **データ可用性(DA)**: authentication path 等の紛争入力の可用性保証。
- **暫定の正直表示**: ①が gas 実測で証明されるまで、現行検証経路を「**BFT 委員会検証**」と明示し、オンチェーン強制可能性を**主張しない**（曖昧な中間を避ける）。
- **ゲート**: gas 実測に foundry allowlist 必須。

### WS4｜クリプト保証プログラム（柱B・実存）
- **最優先**: **QS-SEC-SPHINCS-001 の KAT 実走**。本コントラクトの ADRS は非標準の簡略形で外部ベクタとバイト一致しないため、**対応署名器を同一 ADRS 規則で実装し自己整合 KAT** を組む（`SPHINCSVerifier.sol` A.6 の残タスク）。
- **成果物**:
  - 全プリミティブ（SHAKE256/SHA3/SPHINCS+/Dilithium）の KAT を CI 必須化。
  - 純 Solidity SHAKE/検証器 vs リファレンス（PQClean 等）の**差分ファジング**1本。
  - PR 単位の AI セキュリティレビュー（本リポの security-review/code-review スキル）。
- **ゲート**: forge 実行に foundry allowlist 必須。差分ファジングの参照実装取得はネットワークポリシー確認。

### WS5｜クリプトアジリティ＋ML-DSA-87 ティア（柱C / D2=b）
- **成果物**:
  - **スキーム抽象化**: アルゴリズム ID を `types.rs`（正典）→ `types.ts`／コントラクト（Verifier レジストリ）へ一方向で流す。ハードフォークなしで **ML-DSA-87 / FN-DSA(FIPS206 ~2027) / SQIsign** を差替え可能に。
  - **ティア連動**: `PQ_RESISTANCE…` §4 の T0-T3 に接続。**T2/T3（規制・長期）= ML-DSA-87**、T1 運用鍵 = ML-DSA-65。
  - **CNSA 2.0 アラインメント文書**: 2027 支援 / 2030 撤廃 を営業クロックに。ただし ML-DSA-87 は NSA 要求水準（政府/規制カストディ addressability）。
- **依存**: WS4 の KAT 基盤（新スキーム追加時も KAT 必須）。

### WS6｜外部クロック監視＆トリガー
- **定点観測**: Ethereum **Lean Ethereum / EIP-8141**（Hegotá H2 2026 議論 → PQ 基盤 ~2029）、Bitcoin **BIP-360/361**。
- **明示トリガー**: 「Ethereum が任意アカウントにネイティブ PQ 署名を許した時点で、価値主張を『署名』から『カストディ機構＋閾値-PQC＋規制準拠』へ完全移管し、競合せず**相乗り**」。

## 4. 最初の一手（今スプリント）

1. **foundry を allowlist 追加**（環境設定）— WS3/WS4 の共通ブロッカー解消。これが無いと gas 実測も KAT も動かない。
2. **WS4 起動**: QS-SEC-SPHINCS-001 の自己整合 KAT ＋ 既存 `SPHINCSVerifier*.t.sol` の forge 実走確認。
3. **WS1 起動**: 「PQ カストディ／ポリシー層」1ページャ初稿（閾値-PQC ギャップ＋HNDL）。
4. **WS3 スコープ定義**: 紛争パス PoC の gas 予算・SPHINCS- 加速器・等価マッピングの設計メモ。
